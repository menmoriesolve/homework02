# 需求规格：一个校园失物招领服务，支持发布失物信息、浏览列表、标记已找回和删除信息

## 目标

一个校园失物招领服务，支持发布失物信息、浏览列表、标记已找回和删除信息。核心流程是查询记录、删除记录。

## 用户故事

- 作为业务用户，我希望可以查询记录业务记录，从而完成查询记录目标。
- 作为业务用户，我希望可以删除记录业务记录，从而完成删除记录目标。

## 功能需求

### 查询记录

支持记录列表和按标识查看单条记录。

### 删除记录

按标识删除记录，并在不存在时返回明确错误。

## 数据模型

- 实体：业务记录
- 资源集合：`items`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `title` | string | 是 | 标题 |
| `description` | string | 否 | 描述 |
| `status` | string | 否 | 状态 |

## 验收标准

- Given 系统中已有业务记录数据，When 用户执行查询记录，Then 返回结果并持久化到当前运行状态。
- Given 系统中已有业务记录数据，When 用户执行删除记录，Then 返回结果并持久化到当前运行状态。
- Given 请求缺少必填字段，When 写入数据，Then 返回 400 和字段级错误信息。
- Given 请求不存在的记录，When 读取或删除，Then 返回 404。

## 非功能需求

- 所有写操作必须具备输入校验，错误响应包含可读信息。
- 服务应通过自动化测试验证核心 CRUD 闭环。
- 代码不依赖第三方运行时包，降低演示与部署成本。

## 假设

- MVP 使用单进程内存存储，服务重启后数据清空。
- 接口采用 JSON 和标准 HTTP 状态码。
- 当前版本聚焦核心闭环，不包含真实账号体系。
