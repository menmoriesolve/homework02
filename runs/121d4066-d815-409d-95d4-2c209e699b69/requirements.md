# 需求规格：一个任务清单服务，支持新增、查询、修改和删除任务

## 目标

一个任务清单服务，支持新增、查询、修改和删除任务。核心流程是创建记录、查询记录、更新记录、删除记录。

## 用户故事

- 作为业务用户，我希望可以创建记录任务，从而完成创建记录目标。
- 作为业务用户，我希望可以查询记录任务，从而完成查询记录目标。
- 作为业务用户，我希望可以更新记录任务，从而完成更新记录目标。
- 作为业务用户，我希望可以删除记录任务，从而完成删除记录目标。

## 功能需求

### 创建记录

允许用户创建一条新记录并校验必填字段。

### 查询记录

支持记录列表和按标识查看单条记录。

### 更新记录

允许修改已有记录，并拒绝无效标识。

### 删除记录

按标识删除记录，并在不存在时返回明确错误。

## 数据模型

- 实体：任务
- 资源集合：`tasks`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `title` | string | 是 | 标题 |
| `description` | string | 否 | 描述 |
| `completed` | boolean | 否 | 已完成 |
| `dueDate` | string | 否 | 截止日期 |

## 验收标准

- Given 系统中已有任务数据，When 用户执行创建记录，Then 返回结果并持久化到当前运行状态。
- Given 系统中已有任务数据，When 用户执行查询记录，Then 返回结果并持久化到当前运行状态。
- Given 系统中已有任务数据，When 用户执行更新记录，Then 返回结果并持久化到当前运行状态。
- Given 系统中已有任务数据，When 用户执行删除记录，Then 返回结果并持久化到当前运行状态。
- Given 请求缺少必填字段，When 写入数据，Then 返回 400 和字段级错误信息。
- Given 请求不存在的记录，When 读取或删除，Then 返回 404。

## 非功能需求

- 所有写操作必须具备输入校验，错误响应包含可读信息。
- 服务应通过自动化测试验证核心 CRUD 闭环。
- 代码不依赖第三方运行时包，降低演示与部署成本。

## 假设

- MVP 使用单进程内存存储，服务重启后数据清空。
- 接口采用 JSON 和标准 HTTP 状态码。
- 当前版本聚焦核心闭环，不包含真实账号体系。
